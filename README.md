# Chess Knowledge Graph

A growing, citation-backed knowledge graph of chess: openings, middlegame strategy, tactics, endgames, rules and notation, history, players, events and organizations, computer chess, training, and variants and compositions. An hourly scheduled run researches one new topic, writes it as a node with typed edges to the rest of the graph, checks every move for legality, validates it, and commits it.

## Website

Browse the articles at **https://john1hsu.github.io/chess-graph/**. The site is generated by `scripts/site.py` and redeployed by `.github/workflows/pages.yml` on every push to `main`, so each new article appears there automatically. Articles with a `moves` line or a `fen` position get a board diagram. To preview locally:

```bash
pip install -r requirements.txt
python3 scripts/site.py && python3 -m http.server -d _site 8000
```

## How it's organized

| Layer | What | Where |
|---|---|---|
| Ontology | Chess classes (Opening, Variation, PawnStructure, StrategicConcept, TacticalMotif, MatingPattern, EndgameType, Rule, Player, Event, Game, Title, Engine, Algorithm, CognitiveConcept, …) and typed relations (leadsTo, transposesTo, counters, exemplifiedBy, championedBy, namedAfter, governedBy, holdsTitle, usesTechnique, …) on RDFS/OWL, SKOS and PROV-O | `ontology/ontology.ttl` |
| Nodes | One Markdown article per entity, with YAML frontmatter holding its id, class, hierarchy, typed edges, ECO code, defining moves or key position, status, freshness and per-article provenance | `articles/<domain>/` |
| Graph exports | Linked-data exports regenerated on every commit: JSON-LD, N-Triples, an index | `graph/graph.jsonld`, `graph/triples.nt`, `graph/index.json` |
| Analytics | PageRank centrality, Louvain communities, connected components, coverage by type, domain and status, freshness | `graph/stats.md` |
| Frontier | Nodes existing articles point to but nobody has written yet; the hourly run alternates between expanding this (depth) and the least-covered domain (breadth) | `graph/frontier.md` |

## Guarantees enforced by `scripts/kg.py`

- **Cited:** at least 3 sources per article, at least 2 strong; rules and titles cite a governing body such as the FIDE Handbook; expertise research cites peer-reviewed work; every source is cited and every substantive paragraph carries a citation.
- **Legal:** every opening line, key position and game score is replayed with [python-chess](https://python-chess.readthedocs.io/); an illegal move fails the build.
- **Fresh:** time-sensitive articles (active players, ratings, current rules, engines) are flagged `volatile` and re-verified when they are more than 180 days old.
- **Unique:** no duplicate ids, titles or aliases (transliterations and spellings count); near-paraphrase titles and overlapping text are rejected.
- **Well-formed:** classes and predicates must exist in the ontology.

```bash
pip install -r requirements.txt
python3 scripts/kg.py check                       # validate
python3 scripts/kg.py build                       # validate + regenerate graph/
python3 scripts/kg.py similar "Topic"             # check a candidate for duplicates
python3 scripts/kg.py moves "1.e4 c5 2.Nf3 d6"    # check a line, print its FEN
python3 scripts/kg.py stale                       # time-sensitive articles due for re-verification
```

Steer what gets written by editing `topics/seeds.yaml`. The run playbook is `CLAUDE.md`; the article format is `SCHEMA.md`. The `.nt` and `.jsonld` exports load into RDF tools (Apache Jena, GraphDB, rdflib) or Neo4j via n10s.
